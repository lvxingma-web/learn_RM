# 从主循环读懂自瞄代码：给刚学完 C++ 的同学

这份文档只跟着真实素材版 `team_armor.cpp` 走。目标不是背下每一行，而是能回答：当前数据从哪里来、交给了哪个函数、结果放进哪个变量。先读主流程，再进入函数内部。早期教学版 `main.cpp` 已删除，当前只保留实际素材版入口。

## 0. 先把文件分成三种

- **输入材料**：`task3/demo.avi` 是视频；素材包中的 `yolov5.onnx`、`tiny_resnet.onnx` 是训练好的模型，`calibration.txt` 是标定，`demo.txt` 是 IMU 记录。
- **你要读的源码**：`team_armor.cpp` 负责完整流程；`core.hpp` 存装甲板结构和 PnP；`imu.hpp` 存四元数、时间查找。`CMakeLists.txt` 告诉 CMake 如何编译。
- **程序生成的东西**：`build/team_armor` 是可执行程序；`results/team_result_final.avi` 是标注视频，`results/team_result_final.csv` 是表格记录。`build/CMakeFiles` 等编译中间文件不用读。

读代码时记住：`.cpp` 和 `.hpp` 是人写的源码，`.onnx` 是模型数据，`.avi` 是视频，`.csv` 是用逗号分列的文本表格。

## 1. 全程序只有一条主线

```text
视频文件 → cap 逐帧读成 frame → YOLO 找到 detections
                                    ↓
                    对每块 d：分类 → PnP → 画图 → 写 CSV
                                    ↓
                          保存视频帧 → 读下一帧
```

先认变量。`video` 是视频路径字符串；`cap` 是视频读取器；`frame` 是当前一张图片；`detector` 是 YOLO 检测器；`detections` 是当前帧候选列表；`d` 是列表中正在处理的一块板；`numbers` 是独立分类器；`cal` 是标定数据；`pose` 是 PnP 结果；`imuSeries` 是整个 IMU 文件的数据；`q` 是当前时刻查到的一个四元数；`csv` 是文件输出器；`writer` 是视频输出器。

特别注意：`numbers` 是分类器对象，不是预测编号；`imuSeries` 是整份时间序列，`q` 才是一时刻的姿态。`detector`、`numbers` 是两套不同模型。

## 2. 开始：打开视频并读取第一帧

```cpp
cv::VideoCapture cap(video);
if (!cap.isOpened()) throw std::runtime_error("Cannot open video: " + video);
cv::Mat frame;
if (!cap.read(frame)) throw std::runtime_error("Video has no decodable frames");
```

`cv::VideoCapture` 是类型，`cap` 是变量名，括号里的 `video` 是构造它时给的路径。`cap.isOpened()` 返回成功/失败；`!` 表示取反。`cap.read(frame)` 一边把图片放入 `frame`，一边返回是否成功。`throw` 表示报错并停止当前流程，不是正常播放结束。

## 3. 准备相机参数和两个模型

```cpp
const Calibration cal = readCalibration(calibration);
const ImuSeries imuSeries(imu);
const auto labels = loadLabels(labelsFile);
TeamYolo detector(model, score);
TeamNumber numbers(classifier);
```

`readCalibration(calibration)` 是调用函数：读标定文件，返回数据，放进 `cal`。`TeamYolo detector(model, score)` 是创建对象：加载 YOLO 模型，并保存分数门槛。`TeamNumber numbers(classifier)` 加载九分类模型。`const` 表示这个变量之后不修改；`auto` 让编译器推断类型，`labels` 实际上是字符串列表。

标定文件里的 `K` 和畸变系数供 PnP 使用。`K` 记录焦距参数 `fx/fy` 与图像中心 `cx/cy`。分类器和 YOLO 都是 ONNX 模型，但输入不同：YOLO 看整张图，分类器看已找到的板中间裁图。

## 4. 为什么先准备输出文件

```cpp
const double fps = cap.get(cv::CAP_PROP_FPS)>0 ? cap.get(cv::CAP_PROP_FPS) : 30;
cv::VideoWriter writer(output, cv::VideoWriter::fourcc('M','J','P','G'), fps, frame.size());
std::ofstream csv(csvPath);
```

`fps` 是每秒多少帧。`条件 ? A : B` 是三目运算符：条件成立取 A，否则取 B；这里读不到帧率就用 30。`writer` 用来保存画好标记的视频；`csv` 用来写文本表格。写完表头后，每块候选板写一行，第一行是列名。

## 5. 进入逐帧循环：这几行是整程序核心

```cpp
do {
    auto detections = detector.detect(frame, sizeMode);
    const double time = index / fps;
    Quaternion q;
    const bool hasImu = imuAligned && imuSeries.at(imuStart + time, q, 0.2);
    for (auto& d : detections) {
        numbers.classify(frame, d);
        const Pose pose = estimatePose(d.armor, cal.camera);
        draw(frame, d, pose, labels);
        // 下面把这一块板的数据写进 CSV。
    }
    writer.write(frame);
    ++index;
} while (cap.read(frame));
```

按执行顺序读：`detect` 让 YOLO 看当前 `frame`，返回当前帧的候选列表。`for (auto& d : detections)` 逐块处理；`&` 表示直接使用列表中的那一项，分类器写回 `d` 的结果会留在列表里。`estimatePose` 拿四点和标定算三维位置。`draw` 在图片上画框和文字。`writer.write(frame)` 保存这一帧。`++index` 把帧号加一。末尾 `cap.read(frame)` 读下一帧；读不到时循环结束。实际代码在各步之间还有过滤和错误检查，先抓住这条数据流。

`d.armor` 可以读成“候选 d 里面的 armor”；`cal.camera` 是“标定 cal 里面的 camera”。点号 `.` 用来访问对象里的成员。`const Pose pose` 表示 `pose` 的类型是 `Pose`，计算后在这一轮不修改。

## 6. YOLO 内部先抓输入和输出，不急着算张量

`TeamYolo::detect` 先把原图等比例缩进 640×640 画布，贴在左上角，然后 `net.forward(...)` 得到三个检测头。三个头分别是 80×80、40×40、20×20 网格，每格 3 个 anchor；每个候选有 22 个数，所以最多先提出 `80×80×3 + 40×40×3 + 20×20×3 = 25200` 个候选。这只是尝试数量，不是真实板数。

每个候选的 22 个数包括四角点坐标（8 个数）、目标分数（1 个）、颜色分数（4 个）、编号类别分数（9 个）。程序根据目标分数过滤，再用 NMS 去掉同一块板的重复候选。模型角点先是模型画布坐标；本程序把原图贴左上，所以回原图时除缩放比例，不需要减左边或上边黑框。`d.yoloNumber` 是 YOLO 选中的类别下标。

这一层先不要死磕 `h.ptr<float>(...)`、`anchor` 数组和 lambda。它们只是“从三个输出张量里取数，并把数还原成原图四点”的实现细节；确认主流程后再单独拆。

## 7. 独立分类器看的是小图

`numbers.classify(frame, d)` 先用 `d.armor.points` 的四点把板透视拉正到 128×64 中间图；再裁中间区域，转灰度，等比例缩到不超过 32×32，贴在黑色 32×32 画布的左上角，最后送入 `tiny_resnet.onnx`。它输出 9 个类别分数，程序保存最高分的下标为 `d.numberClass`，分数为 `d.numberScore`。

128×64 是本程序选的教学中间尺寸，不是网络要求的输入大小；网络真正看到的是 32×32。裁剪范围与队内训练预处理尚需核对。分类器训练标签顺序尚未核对，不能把它的下标 8 直接翻译成“非装甲”，也不能假定与 YOLO 的下标顺序相同。当前画面编号主要使用 YOLO 的编号；分类器结果记入 CSV 供检查。

## 8. PnP 回答“板相对相机在哪里”

`estimatePose(d.armor, cal.camera)` 用两组一一对应的四点：图片里的四个像素坐标，与真实板上按毫米给出的四点。小装甲中心距用 135 mm，大装甲用 230 mm，高约 55 mm。`K` 和畸变来自标定。PnP 输出 `pose.tvec=(x,y,z)` 和表示旋转的 `pose.rvec`；本程序真实点以板中心为原点，所以 `tvec` 是板中心相对相机的位置，单位 mm。

平面 PnP 可能交出多个候选姿态。程序要求四个角点在相机前方，再把候选点“投回图片”，比较与输入四点相差多少，选重投影误差较小的解。`z` 是正前方深度；`cv::norm(pose.tvec)/1000` 是相机到板中心的直线距离，单位 m。重投影误差小不单独证明检测目标就是真装甲。

## 9. IMU 回答“机器此刻朝向怎样”

IMU 文本的一行是 `时间戳 qx qy qz qw`。四元数是表示旋转的一组四个数，不是四个角度，也不是装甲坐标。`index/fps` 是视频从开头到当前帧经过的秒数。只有知道视频开始对应 IMU 哪个时间 `imuStart`，才能查 `imuStart + index/fps` 的姿态。`imuSeries.at(..., q, 0.2)` 找相邻采样、必要时插值，若采样间隔超过 0.2 秒则不用；`imuAligned && ...` 在尚未对齐时让右边根本不执行。

当前素材没有说明视频第一帧对应 IMU 哪个时间，也没有确认四元数的坐标方向。默认 CSV 的 IMU 列留空；程序只给相机坐标和由静态安装外参换算的机体坐标，不输出世界坐标。若云台运动，相机到机体的变换还需要当时的云台角度，不能把固定安装旋转当成所有时刻都正确。

## 10. 画面和 CSV 各写什么

`draw(frame, d, pose, labels)` 在 `frame` 上画 P0～P3、颜色、大小、YOLO 编号和距离。`writer.write(frame)` 把画好的这一帧写进视频。`std::ofstream csv(csvPath)` 打开 CSV 文件；`csv << 值 << ','` 往当前行写一个值和逗号；`csv << '\n'` 开始下一行。每检测到一块候选板，写一行；一帧两块就是两行。

真实 CSV 第一条记录可读成：`frame=1`，`time_s=0.033`，`color=blue`，`size=small`，`yolo_number_index=0`，`yolo_score=0.9652`，`classifier_index=8`，`classifier_score=1.0000`。`yolo_score` 是目标分数，不是编号正确率；分类器的 1.0000 是保留四位小数后的最高分，也不证明分类正确。后面的 `p0x...p3y` 是像素坐标，`camera_x_mm...` 是 PnP 的毫米坐标，IMU 列空表示本行没有对齐的姿态记录。

## 11. 遇到语法时按这张表查

| 写法 | 现在先这样读 |
|---|---|
| `const T x = ...` | 创建类型为 T 的变量 x，之后不修改 |
| `auto x = ...` | 由右边推断 x 的类型；不是“自动执行” |
| `x.member` | 取对象 x 里面的 member |
| `object.method(a)` | 让 object 执行 method，把 a 交给它 |
| `for (auto& d : detections)` | 逐个取列表元素，当前元素叫 d；`&` 不复制它 |
| `if (!ok)` | 如果 ok 为假；`!` 表示取反 |
| `A && B` | A 和 B 都真；A 假时不执行 B |
| `条件 ? A : B` | 条件真取 A，否则取 B |
| `++index` | 帧号加 1 |
| `throw std::runtime_error(...)` | 遇到错误，停止当前流程并报告原因 |
| `csv << value` | 把 value 写入文件；类似 `std::cout` 写到终端 |

## 12. 用这三个问题检查自己是否读通主线

1. `frame`、`detections`、`d` 是同一个东西吗？答：不是。一张图片、这张图的候选列表、列表中当前的一块板。
2. YOLO 和独立分类器谁先运行？答：先 YOLO 在整帧找板，再分类器看每块板的中间小图。
3. IMU 列为空，PnP 距离还能算吗？答：能。PnP 用图像四点、真实尺寸和相机标定；IMU 主要用于朝向和坐标变换。
