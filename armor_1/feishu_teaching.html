第 1 步：把“估算矩形”改成“灯条末端四点”

原代码构造了一个大矩形 armor，再用 a.rect.points() 得到它的四个角。这四个角并不一定落在灯条末端。加试要求的点，是左灯上下两端和右灯上下两端的中心。因此我们给灯条增加 top、bottom，给装甲板直接保存四个点。

struct LightBar {
    cv::RotatedRect rect;       // 灯条的旋转外接矩形
    cv::Point2f top, bottom;    // 灯条上端、下端的中心，单位：像素
    std::string color;
    float length;
};
struct ArmorPlate {
    std::array<cv::Point2f, 4> points; // 固定 4 点：左上、右上、右下、左下
    std::string color = "unknown";
    std::string number = "unknown";
    std::string size;
    float confidence = 0;
    bool automaticSize = true;
};

std::array 和 vector 都能存多个元素。这里始终只有 4 个点，因此用 array；Point2f 保存两个小数 x、y。图像左上角是 (0,0)，向右 x 增大，向下 y 增大，所以 y 小的端点在上方。

1.1 找每根灯条的两端

inline std::pair<cv::Point2f, cv::Point2f>
lightEnds(const cv::RotatedRect& r) {
    cv::Point2f p[4];
    r.points(p); // 得到灯条外接矩形的四个顶点，不能假定 p[0] 是左上

    // norm(两点相减) 就是两点间的距离。
    // 矩形相邻两条边一长一短，选择短边。
    const int edge = cv::norm(p[1] - p[0]) <= cv::norm(p[2] - p[1]) ? 0 : 1;

    // 一条短边的中点，以及对面短边的中点，就是两端中心。
    cv::Point2f a = (p[edge] + p[(edge + 1) % 4]) * 0.5f;
    cv::Point2f b = (p[(edge + 2) % 4] + p[(edge + 3) % 4]) * 0.5f;
    if (a.y > b.y) std::swap(a, b); // 排成：上端在前，下端在后
    return {a, b};
}

例如灯条长 70 像素、宽 10 像素。我们取两个 10 像素短边的中点，它们相距约 70 像素。灯条倾斜时也用同样的方法。% 4 表示下标绕回去，例如 p[4 % 4] 就是 p[0]。std::pair 用来一次返回两个点，first 是上端，second 是下端。这里的点来自外接矩形，是对真实亮区末端的估计；亮区过曝、遮挡会影响位置。

第 2 步：标颜色和大小

传统方法的颜色来自蓝色/红色二值图的来源。大小先用“左右灯中心距离 ÷ 平均灯条长度”估计。用比例而不是固定像素，能减轻远近变化的影响。

inline void setArmorSize(ArmorPlate& a, const std::string& mode) {
    a.automaticSize = mode == "auto";
    if (!a.automaticSize) { a.size = mode; return; } // 可以手动指定真实大小

    const auto lc = (a.points[0] + a.points[3]) * 0.5f; // 左灯中心
    const auto rc = (a.points[1] + a.points[2]) * 0.5f; // 右灯中心
    const double h = (cv::norm(a.points[3] - a.points[0]) +
                      cv::norm(a.points[2] - a.points[1])) / 2.0;
    const double boundary = (135.0 / 55.0 + 230.0 / 55.0) / 2.0;
    a.size = h > 0 && cv::norm(rc - lc) / h > boundary ? "large" : "small";
}

小装甲物理比例约 135/55=2.45，大装甲约 230/55=4.18。教学初判取两者中点约 3.32，大于它暂判 large，否则 small。这个值来源于题目尺寸，不是训练出来的最佳阈值。侧面透视会压缩两灯间距，可能把大装甲判小。做 PnP 初次验证时，优先用 --type small 或 --type large 指定你确认的真实类型；大小用错会直接影响距离。

检查方法：选择已知小/大装甲的正面帧，看 small/large 标签；再看侧面是否误判。颜色、大小、编号是三个独立字段。当前无模型编号显示 unknown，是正常状态。

第 3 步：接入 32×32 编号分类模型

分类模型像一道选择题：你给它一张只含编号区域的小图，它给出 9 个类别分数。它本身不负责在整张视频里找装甲；装甲位置已经由前面的灯条检测找到。9 类分别包含 1～5、哨兵、前哨站、基地、不是装甲板，但数组里谁排第 0、第 1，必须以训练代码为准，不能按题目列举顺序猜。

ONNX 是模型文件的一种格式，里面保存训练得到的网络结构和权重。你目前的任务是“推理”：加载现成模型，把图片送进去并读取结果；不需要先自己训练。OpenCV 的 dnn 模块帮 C++ 执行这些计算。

3.1 先把斜着的装甲变正

四点围成的区域可能倾斜。透视变换相当于把它拉成正面矩形，便于按固定比例裁出中间编号。以下摘自 models.hpp；这些代码属于 classify() 函数内部，不能单独粘到 main 的任意位置。

const int height = 64; // 教学中间图高度；不是模型输入高度
const int width = cvRound(height * (a.size == "large" ? 230.0 : 135.0) / 55.0);
const std::array<cv::Point2f,4> dst{{{0,0}, {(float)width-1,0},
    {(float)width-1,(float)height-1}, {0,(float)height-1}}};
cv::Mat rectified;
cv::warpPerspective(frame, rectified,
    cv::getPerspectiveTransform(a.points.data(), dst.data()), cv::Size(width,height));

a.points 是原图四点，dst 是拉正后四点。getPerspectiveTransform 求“怎么拉”，warpPerspective 真正产生拉正后的图片。64 只是参考实现中的中间画布尺寸，最终输入仍是 32×32；队内若采用其他裁剪方式，应照队内方式修改。roi_left、roi_right、roi_top、roi_bottom 来自队内裁剪代码，含义是占拉正图宽高的比例。

假设灰度裁剪图是 20×40，缩放比例 min(32/20,32/40)=0.8，得到 16×32；把它放在 32×32 画布左上，右边补黑。CV_8U 表示每像素 0～255 的单通道整数。blobFromImage 把图片整理成网络需要的输入数据；scale 是否等于 1/255、是否还有均值处理，必须看队内模型协议。当前参考适配器支持缩放，不代表支持所有训练预处理。

3.3 取最高分，并处理“不是装甲板”

int best = 0;
for (int k = 0; k < 9; ++k) {
    if (out.at<float>(k) > out.at<float>(best)) best = k;
}
a.confidence = out.at<float>(best);
a.number = a.confidence >= confidence ? labels[best] : "unknown";
// 高置信度且是“不是装甲板”时丢弃；低置信度保持 unknown。

第 4 步：YOLO 是什么，怎样接入

YOLO 是一类目标检测网络。传统方法是你手写“颜色差、细长比例、两灯配对”等规则；YOLO 是把整张图交给训练好的网络，由网络输出候选目标的位置和分数。普通目标检测常给矩形框；你队里的模型还要给四个角点，这是经过专门设计/训练的输出。随便下载一个通用 YOLO 模型，不会自动认识 RM 装甲并产生灯条端点。

两条路线：路线 A：原来的灯条检测 → 四点 → 小图编号分类器 → PnP；路线 B：队内 YOLO → 解码出装甲四点和类别 → PnP。加试题的几何/PnP 学习可以先沿 A 完成。B 能否取代 A，要看队内模型确实输出什么。你不必把 YOLO 和分类器混为一个模型。

4.1 推理的四件事

①加载 ONNX；②把原图缩放、补边、整理成网络输入；③forward 计算；④把输出张量里的数字按队内规则解码为四点、编号、置信度，并去掉重复候选。张量可以先理解为多维数组，例如 [1,N,22]：1 张输入图，N 个候选，每个候选 22 个数。

net = cv::dnn::readNetFromONNX(model); // 加载现成模型，构造时执行
// detect() 内：左上对齐缩放，右侧和底部补黑
const double resizeScale = std::min((double)inputW/frame.cols,
                                    (double)inputH/frame.rows);
cv::Mat input = cv::Mat::zeros(inputH,inputW,CV_8UC3);
const int w = std::clamp(cvRound(frame.cols*resizeScale),1,inputW);
const int h = std::clamp(cvRound(frame.rows*resizeScale),1,inputH);
cv::resize(frame, input(cv::Rect(0,0,w,h)), cv::Size(w,h));
net.setInput(cv::dnn::blobFromImage(input, scale,
    cv::Size(inputW,inputH), cv::Scalar(), swapRB));
cv::Mat out = oneOutput(net); // 内部 net.forward，输出网络预测

例如原图 1440×1080、假设模型输入 640×640，缩放比例是 640/1440≈0.444，缩成约 640×480，放左上，下面补黑。这只是解释算式的例子，实际 inputW/inputH 必须取队内值。swapRB 决定 OpenCV 的 BGR 是否转成模型需要的 RGB；scale 决定像素归一化。

4.2 “每行 22 个数”不是完整说明书

仅知道 22，无法确定第几列是类别、第几列是角点、有没有 objectness（目标存在分数），也无法确定输出是 [1,N,22] 还是 [1,22,N]。所以适配器用 yolo.yml 明确记录 class_indices（9 列）、keypoint_indices（8 列）、objectness_index（没有则 -1）、labels、输出布局、坐标单位。这些值必须逐项抄自队内解码代码；示例里的 -1、TODO 会被程序拒绝。

const float* v = rows.ptr<float>(row); // 一行候选的 22 个数
for (int k = 0; k < 4; ++k) {
    // points 是配置中的列下标，顺序必须为 LT,RT,RB,LB 的 x,y。
    double x = v[points[k*2]], y = v[points[k*2+1]];
    if (units == "normalized") { x *= inputW; y *= inputH; }
    a.points[k] = cv::Point2f(x/resizeScale, y/resizeScale); // 只除缩放
}

为什么不减黑边？因为这份预处理把图片贴在左上，左/上没有偏移，点坐标只受到缩放。必须同时满足：队内也用这个方式、输出角点定义与输入画布一致。如果预处理改成居中补边，公式也要改变，不能机械照抄“只除缩放”。此处遵守题目要求，等待队内推理代码进一步核对。

NMS 是“去重复框”：多个候选可能都指向同一块装甲，保留分数较高的候选。完整代码检查四点能否构成凸四边形，再用四点外接框做 NMS；它是参考去重方式，若队内模型已带 NMS 或使用不同策略，应修改。颜色目前沿两根灯的线段采样蓝红差，弱颜色会记 unknown；这是临时策略，若模型直接预测颜色，以队内字段为准。

第 5 步：用 PnP 求相机前的 xyz 和距离

PnP 可以理解为：我知道这块装甲实际有多大，也知道四个点在图片里出现在哪里，再加上这台相机的成像参数，就能估计装甲相对于相机的位置和姿态。四点是像素坐标；实际尺寸是毫米；相机内参负责把两者联系起来。只用图像中的宽高像素，不能可靠得出真实距离。

5.1 准备真实相机标定

需要 camera_matrix（3×3 内参，包含 fx、fy、cx、cy）、distortion_coefficients（镜头畸变）、image_width、image_height。可以用棋盘格标定得到，或者使用队内对应相机、对应分辨率的标定结果。示例文件焦距为 0，故意不能运行，防止把假数据算出的距离当成结果。初学阶段优先获取真实标定，避免同时学习标定采集和 PnP。

这份程序要求标定分辨率与原视频一致。显示缩小到窗口不影响解算，因为传给 PnP 的是原图四点；如果以后先缩小图像再检测，必须把点还原或正确调整内参，两者不能混用。

5.2 定义真实装甲的四个点

inline std::vector<cv::Point3f> objectPoints(const std::string& type) {
    const float w = type == "large" ? 230.0f : 135.0f; // 两灯中心间距，mm
    const float h = 55.0f; // 灯条高度，mm
    // 装甲中心为原点；x 向右、y 向下。四点位于同一个平面 z=0。
    return {{-w/2, -h/2, 0},  // 左上，对应图像 P0
            { w/2, -h/2, 0},  // 右上，对应图像 P1
            { w/2,  h/2, 0},  // 右下，对应图像 P2
            {-w/2,  h/2, 0}}; // 左下，对应图像 P3
}

小装甲左上点就是 (-67.5,-27.5,0) mm。z=0 是我们给装甲自身定义的局部平面，不表示它在相机前的深度为零。PnP 会求出这个平面如何旋转、平移到相机坐标系中。这里尺寸按题目提供的近似值；实际灯条发光端点间距与模型尺寸应进一步核实。

5.3 把四对点和标定交给 OpenCV

const std::vector<cv::Point2f> image(a.points.begin(), a.points.end());
const auto object = objectPoints(a.size);
std::vector<cv::Mat> rotations, translations;
cv::solvePnPGeneric(object, image, c.K, c.distortion,
    rotations, translations, false, cv::SOLVEPNP_IPPE);

object 是实际 3D 点，image 是对应的图像 2D 点，c.K 是内参，c.distortion 是畸变。输出 rotations 是旋转向量，translations 是平移向量。IPPE 适合平面点；平面可能产生多个候选解，因此完整 estimatePose() 会逐个检查，保留点都在相机前且重投影误差最小的那个。

5.4 用重投影检查“算得对不对”

std::vector<cv::Point2f> projected;
cv::projectPoints(object, r, t, c.K, c.distortion, projected);
double squared = 0;
for (size_t k = 0; k < image.size(); ++k) {
    const auto d = projected[k] - image[k]; // 预测位置减原来测到的位置
    squared += d.dot(d); // dx² + dy²
}
const double error = std::sqrt(squared / image.size()); // RMS 误差，单位像素

PnP 是由图片反推空间位置；projectPoints 则把这个空间位置再投回图片。两组点越接近，说明几何解释越吻合。画面黄色点是检测点，紫色点是重投影点。默认 --max-error 5 是教学检查门槛，意思是误差超过 5 像素就暂不接受，并不是队内规定或验证后的最佳数值。误差小也不保证绝对距离正确：错误大小、错误焦距仍可能产生貌似合理的投影。

5.5 显示 xyz 和距离

Pose pose = estimatePose(a, camera);
// 通过有效性与重投影误差检查之后：
double x_m = pose.tvec[0] / 1000.0;
double y_m = pose.tvec[1] / 1000.0;
double z_m = pose.tvec[2] / 1000.0;
double distance_m = cv::norm(pose.tvec) / 1000.0; // sqrt(x²+y²+z²)，mm 转 m

相机坐标通常 x 向右、y 向下、z 向前。tvec 是装甲局部原点（此处是装甲中心）在相机坐标系中的位置。z 是向前的深度，distance 是到中心的直线距离；目标偏离画面中心时，二者不同。物体尺寸采用毫米，所以 tvec 也是毫米，除以 1000 才是米。rvec 的三个数不是直接的欧拉角，先不拿它当 yaw/pitch/roll。

--type small 仅在你确认目标是小装甲时使用。没有 --calib 时显示 no_calibration；解算失败显示 pnp_failed；误差过大显示 reprojection_rejected。csv 中无效 xyz/距离留空。

第 6 步：读取 IMU 的 xyzw，理解坐标变换

IMU 提供姿态，可以理解为“相机/云台现在朝哪个方向”。四元数是表示旋转的一种方式，先学会顺序和调用，再补数学推导。题目要求顺序 qx qy qz qw，不能当成 qw qx qy qz。IMU 不会自动提供装甲距离；距离仍来自 PnP。

6.1 文件格式和读取

# imu.txt 的一种约定：时间单位秒，每行一个姿态
# timestamp_s qx qy qz qw
0.000 0 0 0 1
0.033 0 0 0 1
0.067 0 0 0 1
# 以上是说明格式的“无旋转”例子，不是你的真实 IMU 数据。
const int first = constant ? 0 : 1; // 一行 4 个数为固定姿态；5 个数首列是时间
Quaternion q{values[first], values[first+1], values[first+2], values[first+3]};
q.normalize(); // 除以四元数长度，避免数值不满足单位四元数
samples.push_back({time,q});

完整 imu.hpp 接受“timestamp_s + xyzw”，或者只有一行 xyzw 的固定姿态。四元数 (0,0,0,1) 表示无旋转。该文件格式是这份程序的接口约定；真实文本若还有别的列、使用毫秒或时间顺序不同，要改读取逻辑，不能直接丢进去。

6.2 用时间对齐，不是第几行对第几帧

const double time = index / fps; // 对恒定帧率视频估计当前帧时间
Quaternion attitude;
const bool imuValid = imu && imu->at(time + o.imuOffset, attitude);

例如 30 fps，第 30 帧（从 0 计数）的时间约 1 秒。若视频第 0 帧对应 IMU 的 100 秒，--imu-offset 100。IMU 采样可能比视频快，at() 用相邻两条姿态做 SLERP 插值，估计当前帧的姿态；超出 IMU 时间范围就不输出变换结果。index/fps 对可变帧率、掉帧或不同步录像只是近似，真实系统应使用真实帧时间戳。偏移量必须来自同步信息，不能凭感觉凑。

6.3 相机、IMU、参考坐标不是同一个坐标系

cv::Matx33d referenceFromImu = attitude.rotation();
// 如果文本表示“参考坐标 → IMU”，要取反向旋转。
if (o.imuDirection == "imu-from-world") referenceFromImu = referenceFromImu.t();
// 先从相机变到 IMU，再将方向转到参考坐标轴；单位仍是 mm。
axes = referenceFromImu *
    (extrinsic->imuFromCamera * pose.tvec + extrinsic->translationMm);

extrinsic 是相机与 IMU 的安装外参。R_imu_camera 把相机方向转到 IMU 方向；t_imu_camera_mm 是相机原点在 IMU 坐标中的位置。两者必须是真实安装标定值，不会因为设备装在一起就自动相同。--imu-direction 指定四元数究竟表示哪个方向，必须查队内约定。

此处 axes 的含义是：用参考方向表示、以当前 IMU 位置为原点的装甲相对向量。只有姿态、没有 IMU 在世界中的平移，不能称为绝对世界位置。csv 将它标为 oriented_axes_current_imu_origin，和 cam xyz 分开保存。
